# Trust and execution boundaries

Browser access uses native Cloud Run IAP. The backend verifies the signed IAP assertion, issuer, and exact service audience; it never trusts a plain email header. Operators can import transactions, attach evidence, inspect cases, and request reassessment. Only configured reviewers can register or retire policies, alter automation rules, and record reviewed decisions. The worker verifies Google-issued service-account ID tokens and separates the Pub/Sub/Scheduler caller from explicitly allowed source connector identities. There is no anonymous mode or local development auth bypass.

Source document text, filenames, supplier descriptions, and retrieved policy contents are untrusted model inputs. They cannot invoke arbitrary tools. Specialists return typed findings, and cited identifiers must exist in the supplied evidence. Model estimates do not grant action permissions: a deterministic authorization gateway applies configured rules, completeness requirements, independence counts, prediction requirements, and expiry. Prompt injection resistance in free text is not a formal guarantee; evaluate with the organization's adversarial documents before enabling automatic clearance.

The public API has no arbitrary prompt surface. Explanations accept only `decision`, `evidence`, `policy`, or `next_steps`; extra fields and other section values are rejected. The platform does not answer unrelated questions. Internal model instructions explicitly prohibit obeying embedded unrelated requests or giving general legal advice.

Content hashes and declared parent links deduplicate source ancestry. Matching between unique content roots and authenticated connector identities prevents duplicate bytes or repeated identity assertions from creating extra independent votes. This is not proof that a document is authentic. User uploads remain unattested. Only allowed connectors can assert an origin, and the identity is taken from the verified token, never a submitted email address.

Decision validity is checked against current database versions, the full policy corpus, and expiry. Reviewed decisions use compare-and-swap to reject concurrent reviewer changes. Action requests are bound to the decision's version as well as the evidence snapshot. The application records external execution only from an authenticated receipt tied to a known published request. A queued request or application hold is not a bank hold.

A connected ERP/payment system must check `/internal/decision-check` immediately before executing, use the request ID as its own idempotency key, and return an execution receipt. There is an unavoidable distributed-system interval between preflight and an external action. Integrations needing stronger guarantees must implement conditional authorization and idempotency atomically in their own transaction. This prototype does not promise exactly-once money movement or automatic reversal.

Cloud SQL uses IAM database login for the runtime. A separate migration identity reads its password from Secret Manager and grants restricted application table access. Runtime audit rows are append-only, with chained hashes and an update/delete rejection trigger. Administrators still control the database and bucket: this is tamper-evident application history, not a claim of independently notarized or administrator-proof storage. Use a reviewed retention policy, CMEK and access separation for regulated deployments.

The Terraform state contains sensitive migration credentials and must remain in the private state bucket. Never commit state, environment credentials, or service-account keys. Use ADC or Workload Identity rather than downloading long-lived keys. Records and model context stay within the configured Google Cloud project/services; choose document, search, analytics and model regions to meet your organization's residency requirements.

## Public prototype access

`PUBLIC_DEMO=true` opens the application without Google sign-in, only in the seeded `synthetic-*` organization. Anonymous visitors have read-only access; all API mutations and internal worker endpoints remain blocked. BigQuery analytics are not exposed to anonymous callers because the table may contain other organizations. Set the GitHub variable `PUBLIC_DEMO=false` and redeploy to require IAP again. Main-branch commits explicitly marked `[deploy]` trigger the full release pipeline, as do manually dispatched releases.
